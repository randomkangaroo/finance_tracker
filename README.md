# Finance Tracker

A single-user, offline desktop app for tracking personal finances. It's built with Tauri 2: a
Rust backend that owns a local SQLite database, and a React + TypeScript (Vite) frontend.
Nothing leaves your machine.

- [`SPEC.md`](SPEC.md): requirements, data model and the decisions log
- [`docs/tasks/`](docs/tasks/): milestone checklists ([M0 – Setup](docs/tasks/M0-setup.md),
  [M1 – Core Ledger](docs/tasks/M1-core-ledger.md))
- [`CLAUDE.md`](CLAUDE.md): a condensed guide to the codebase's conventions

## Prerequisites

- **Rust** stable via [`rustup`](https://rustup.rs), 1.85 or newer (the crate uses edition
  2024), with the `rustfmt` and `clippy` components:
  `rustup component add rustfmt clippy`
- **Node.js** LTS and npm
- **Tauri's system dependencies** (WebKitGTK 4.1 and friends on Linux). Follow the
  [Tauri prerequisites guide](https://tauri.app/start/prerequisites/) for your OS.

Then install the frontend dependencies:

```sh
npm install
```

The first `npm run tauri dev` or `cargo` command compiles every Rust dependency, so expect it
to take a few minutes.

## Development

```sh
npm run tauri dev     # run the app: Vite on :1420 plus the Rust backend, both hot-reloading
npm run tauri build   # release bundle, in src-tauri/target/release/bundle/
```

### Checks

Run everything before committing:

```sh
npm run check
```

That runs each of the checks below and fails on the first problem. There's no CI yet (M0
0.12 is deferred), so this is the only thing enforcing them.

| Command                | What it checks                                                     |
| ---------------------- | ------------------------------------------------------------------ |
| `npm run format:check` | Prettier formatting (`npm run format` fixes it)                    |
| `npm run lint`         | ESLint, with type-aware `typescript-eslint` and React hooks rules  |
| `npm run typecheck`    | `tsc --noEmit` for `src/` and `vite.config.ts`                     |
| `npm test`             | Vitest component and unit tests (`npm run test:watch` to watch)    |
| `npm run check:rust`   | `cargo fmt --check`, `cargo clippy -D warnings` and `cargo test`   |
| _(last step)_          | `git diff --exit-code src/bindings.ts`: the bindings are committed |

Cargo commands run from `src-tauri/`. To run part of the Rust suite, pass a name filter:
`cargo test db::tests::` for one module, or a substring of a test name for one test.

### Regenerating the TypeScript bindings

`src/bindings.ts` holds the TypeScript types and typed wrappers for every Rust command. It's
generated by `tauri-specta`, so never edit it by hand. It's rewritten whenever you:

- launch a debug build (`npm run tauri dev`), or
- run `cargo test export_bindings` in `src-tauri/`, which doesn't open a window.

After changing a command or a type it returns, regenerate the file and commit it alongside
the Rust change. Renamed fields then show up as TypeScript errors in `npm run typecheck`.

### Where the database lives

The app stores everything in one SQLite file, `finance.db`, in Tauri's app data directory
for the identifier `com.moulttho.finance-tracker`:

| OS      | Path                                                                    |
| ------- | ----------------------------------------------------------------------- |
| Linux   | `~/.local/share/com.moulttho.finance-tracker/finance.db`                |
| macOS   | `~/Library/Application Support/com.moulttho.finance-tracker/finance.db` |
| Windows | `%APPDATA%\com.moulttho.finance-tracker\finance.db`                     |

On Linux, `$XDG_DATA_HOME` replaces `~/.local/share` if it's set. The running app shows the
exact path under **Settings → About**. To start from an empty database, quit the app and
delete the file. It's recreated and migrated on the next launch. Since it runs in WAL mode,
also delete the `finance.db-wal` and `finance.db-shm` files beside it if they're there.

## Architecture rules

The Rust backend in `src-tauri/src/` is layered:

| Module      | Contents                                                      |
| ----------- | ------------------------------------------------------------- |
| `lib.rs`    | Tauri builder setup: managed state, commands, bindings export |
| `main.rs`   | Calls `finance_tracker_lib::run()`                            |
| `error.rs`  | `AppError`, the error type every command returns              |
| `commands/` | Thin `#[tauri::command]` wrappers, one file per area          |
| `domain/`   | Domain types and business logic                               |
| `db/`       | Connection setup, pragmas, migrations (`db/sql/NNN_*.sql`)    |

- **`domain/` and `db/` must never import `tauri`.** Only `commands/` and `lib.rs` may. This
  keeps the business logic and database code testable with plain `cargo test`.
- **Never edit a migration once it's committed; add a new one.** Migrations live in
  `src-tauri/src/db/sql/` as `NNN_description.sql` and are listed in order in
  `db/migrations.rs`. `rusqlite_migration` records how many have run in
  `PRAGMA user_version`, so an existing database never re-runs an old file. Editing one
  would leave existing databases and new ones with different schemas.
- **Rust owns the data.** The frontend calls typed commands from `src/bindings.ts` and never
  writes SQL. Commands stay thin: they validate input, call into `domain/`/`db/`, and return
  `AppResult<T>`.
- **Money is integer minor units** (cents): `i64` in Rust, a plain `number` in TypeScript.
  Never use floating point, including when parsing what the user types. Convert to a decimal
  string only when rendering. Amounts are signed, with negative meaning money out.
- **Balances are derived** as `opening_balance + SUM(amount)`, never stored.

The frontend in `src/` is split into `api/` (TanStack Query hooks), `routes/` (one folder per
screen), `components/` (shared UI with CSS Modules), `lib/` (pure helpers, no React) and
`styles/` (the global reset and design tokens). See `CLAUDE.md` for details.

## Pinned dependency versions

Most dependencies use normal semver ranges and are held in place by `Cargo.lock` and
`package-lock.json`. The ones below are pinned exactly (`=x.y.z` in `src-tauri/Cargo.toml`)
because they have to move together.

| Crate               | Version       | Why                                                                                                     |
| ------------------- | ------------- | ------------------------------------------------------------------------------------------------------- |
| `tauri`             | `2.12.3`      | `tauri-specta` hooks into Tauri's command/invoke internals, so the pair must be known to work together. |
| `tauri-build`       | `2.7.2`       | Build-time companion to `tauri`; pinned so it can't drift ahead of the `tauri` version.                 |
| `specta`            | `2.0.0-rc.25` | This is the newest current version of `specta`.                                                         |
| `specta-typescript` | `0.0.12`      | The TypeScript exporter for `specta`; this is the version `tauri-specta 2.0.0-rc.25` is built against.  |
| `tauri-specta`      | `2.0.0-rc.25` | Release candidate; must match `specta` exactly.                                                         |

`tauri-specta`, `specta` and `specta-typescript` versions come from the same `tauri-specta`
release. The frontend `@tauri-apps/api` (2.12.x) is kept on the same minor version as the
`tauri` crate, as Tauri expects.

Other notable choices (ranges, not exact pins):

- `rusqlite` `0.40` with the `bundled` feature, so every machine uses the same compiled-in
  SQLite instead of the system library. `rusqlite_migration` `2.6` supports this `rusqlite`.
- `time` `0.3` with `serde`, `formatting` and `parsing`.
- Frontend: `react` 19, `react-router` 8, `@tanstack/react-query` 5.

**Bumping the pinned set:** check the `tauri-specta` release notes for the `specta`,
`specta-typescript` and `tauri` versions it targets, update all of them together, then run
`cargo build` and regenerate the bindings.
